# 학관 온라인 주문 프로그램

## Data class

Menu - 음식 데이터 클래스: 음식의 이름, 음식의 타입(fry fry, 따스한동, H:plate, 든든한동, Asian Market)

Cook - 요리사 : 주문을 받고 요리를 하고 음식을 줌. 음식을 주문 받은 뒤에 1초마다 조리중 메시지 출력, 3초뒤에 조리 완료 출력

Customer - 손님: 주문을 하고 음식을 받음. 주문시에 잔액을 확인. 잔액이 부족하면 에러메시지.

Order: 주문 관리. 주문번호, 주문상태, 주문개수, 식당타입

Service: 각각의 과정들

Manager: 이어 주는 역할

메뉴
1. 회원 메뉴
2. 관리자 메뉴

1.1 회원가입 -> 회원정보가 텍스트파일 형태로 저장됌. (이름, 학번, 아이디, 비밀번호, 잔액)

1.2  메뉴 주문

2.1 메뉴 추가

2.2 메뉴 출력

2.2 메뉴 수정

2.3 메뉴 삭제





## 프로젝트 주제 및 개요(해당 주제를 선택한 이유 포함)
점심시간과 저녁시간에 학관에 가면 사람이 굉장히 많습니다.
적당히 많은게 아니라 줄이 너무 길어져서 학관 끝에서 끝까지 채울 정도로 깁니다.
그래서 학생들이 점심시간에도 불구하고 줄을 최소 10분에서 많게는 30분 기다려서 받는 문제들이 발생합니다.
학교에서 푸드포인트를 장려하는 가운데 푸드포인트를 주로 쓰게되는 학관에서
이런 문제로 식당을 이용하기 어려워지면 문제가 발생합니다.
따라서 학생들의 쾌적한 학생식당 이용을 위해 온라인 주문시스템을 도입하고자 합니다.

생각하는 방향으로는 학관식당 식탁에 QR코드를 도입하여 핸드폰으로 주문을 할 수 있게 되기를 구상중입니다.

이 프로그램은 이러한 문제해결을 위한 시스템입니다.

● interface 사용 이유

interface를 사용한 이유는 함수를 구현하기 전에 미리 설계서를 작성해놓고
거기에 따라서 동작하게 하기 위함입니다. 프로젝트에서는 실수로 필요한 구성에 필요한 함수를
구현을 놓치거나 의도와 다르게 구현할 때가 있습니다. interface는 설계서로서
그러한 실수들을 사전에 막을 수 있게 해줍니다.
또한 잘 구성된 interface는 그 자체로 프로젝트 구조를 파악하고 설계하는데 도움을 줍니다.

● overriding / overloading 적용 부분 설명

overriding은 Customer, Menu data Class에서 ToString에 사용하였습니다.
또한 overloading은 Customer, Menu, CustomerServiceImpl, Manager, MenuService, MenuServiceImpl Class에서
생성자에서 여러 인수를 받기 위해 사용하였습니다.
