# 학관 온라인 주문 프로그램


## 프로젝트 주제 및 개요
점심시간과 저녁시간에 학관에 가면 사람이 굉장히 많습니다.
적당히 많은게 아니라 줄이 너무 길어져서 학관 끝에서 끝까지 채울 정도로 깁니다.
그래서 학생들이 점심시간에도 불구하고 줄을 최소 10분에서 많게는 30분 기다려서 받는 문제들이 발생합니다.
학교에서 푸드포인트를 장려하는 상황에서, 푸드포인트를 주로 쓰게되는 학관에서
이런 문제로 식당을 이용하기 어려워지면 학생들의 식사 편의성이 떨어질 수 있습니다
따라서 학생들의 쾌적한 학생식당 이용을 위해 온라인 주문시스템을 도입하고자 합니다.

제가 구상한 방향은 학관 식당의 식탁에 QR코드를 배치하여,
학생들이 휴대폰으로 메뉴를 확인하고 주문할 수 있도록 하는 것입니다.
이 프로그램은 이러한 문제를 해결하기 위한 학관 온라인 주문 시스템입니다.


● 데이터 필드 구성 설명

1. Customer
   1. name: 고객의 이름
   2. userId: 고객의 아이디
   3. password: 고객의 비밀번호
   4. balance: 고객의 잔고
2. Menu
   1. name: 메뉴 이름
   2. type: 메뉴 타입(1. 든든한동, 2. 따스한동, 3.Fry Fry, 4 H:Plate, 5. Asian Market)
   3. price: 메뉴 가격
   4. description: 메뉴 설명
   5. stock: 남은 수량

● 클래스 구조 설명

model(Customer, Menu)
service(Manager, CustomerService, CustomerServiceImpl, MenuService, MenuServiceImpl)
Main


● interface 사용 이유

interface를 사용한 이유는 함수를 구현하기 전에 미리 설계서를 작성해놓고
거기에 따라서 동작하게 하기 위함입니다. 프로젝트에서는 실수로 필요한 구성에 필요한 함수를
구현을 놓치거나 의도와 다르게 구현할 때가 있습니다. interface는 설계서로서
그러한 실수들을 사전에 막을 수 있게 해줍니다.
또한 잘 구성된 interface는 그 자체로 프로젝트 구조를 파악하고 설계하는데 도움을 줍니다.
어떤 클래스가 어떤 기능을 담당해야 하는지 명확해지기 때문에, 코드의 역할을 나누고 관리하기가 더 쉬워집니다.

● overriding / overloading 적용 부분 설명

overriding은 Customer, Menu data Class에서 ToString에 사용하였습니다.
또한 overloading은 Customer, Menu, CustomerServiceImpl, Manager, MenuServiceImpl Class에서
클래스의 생성자에서 사용하였습니다. 생성자를 여러 개 만들어 상황에 따라 다른 인수를 받을 수 있도록 하였습니다.

● 추가 기능 3가지 설명

기본적인 CRUD는 Menu 추가, 수정, 삭제, 출력 기능입니다.
추가적으로 구현한 기능은 회원가입, 로그인, 현재 로그인 사용자 확인, 음식주문, 회원목록 출력, 메뉴 분석, 메뉴 검색 기능을 구현하였습니다.

처음에는 추가 기능을 3가지만 구현하려고 했지만, 제가 생각한 프로그램을 완성하려면 결국 사용자와 메뉴 사이의 상호작용이 필요하다고 느꼈습니다.
그래서 회원가입과 로그인 기능을 추가하였고, 음식 주문 기능도 함께 구현하였습니다.

또한 사용자 관련 기능이 CRUD와 비슷하게 보일 수 있다고 생각하여, 메뉴 검색과 메뉴 분석 기능도 추가로 구현하였습니다.

이제 추가기능을 간단하게 설명하겠습니다.

1. 회원가입기능: 사용자에게 이름, 아이디, 잔액을 입력받아 회원 리스트에 추가합니다.
2. 로그인기능: 회원리스트에 입력받은 회원정보와 일치하는 회원이 있을 경우 로그인 되었음을 알립니다.
3. 현재 로그인 사용자 확인: 현재 로그인 사용자 이름을 알려줍니다.
4. 음식주문: 음식을 주문합니다. 잔고는 사용자 전체 잔고에서 음식의 총 금액만큼 차감합니다.
5. 회원 목록 출력: 회원 목록을 출력합니다. 회원정보와 회원이 주문한 음식내역이 포함되어있습니다.
6. 메뉴 검색: 메뉴 이름을 입력받아 해당하는 키워드를 가진 메뉴이름의 정보를 검색합니다.
7. 메뉴 분석: 각 음식점별로 제공하는 메뉴의 개수를 출력합니다.

● 구현 과정에서 어려웠던 점 (2가지 이상)
1. 회원가입과 로그인 기능을 구현할 때 조금 어렸습니다. 파일을 이용해서 프로그램이 종료된 뒤 다시 실행해도
   회원 정보가 계속 유지되길 원했습니다. 그래서 회원가입이 성공한 뒤에는 리스트에 회원 정보를 저장하고
   로그인도 회원정보 리스트를 통해 확인하는 식으로 진행하였습니다. 그리고 회원정보를 저장, 로드 하여
   한번 가입된 회원 정보가 계속 유자되게 하였습니다. 
   그리고 로그인을 로그인을 성공하면 그 객체를 리턴하는 식으로 각 회원별로 독립된 정보를 저장하고 또 로그인을 통해
   다시 불러올 수 있게 하였습니다.
2. 또한 데이터 클래스의 필드를 정하는 과정도 어려웠습니다. 처음에는 필요한 변수를 간단하게 정했지만, 실제로 코드를 작성하다 보니 추가하거나 수정해야 하는 변수가 생겼습니다.
   이처럼 프로그램을 구현하면서 데이터 구조를 계속 수정해야 하는 점이 어려웠습니다.
3. Class injection을 적용하는 과정이 복잡했습니다. 특히 List를 쓰고 실제로 넣을 때는 ArrayList를 넣는 것이
더 좋은 코드라고 하는데 처음에는 인터페이스인데 어떻게 구현 코드에 들어갈 수 있는지 이해가 안되서 좀 헷갈렸습니다. 

## 수업 회고 및 느낀점
● 프로젝트를 진행하면서 새롭게 배운 점

제가 해결하고 싶은 문제를 실제로 구현해볼 수 있다는 점이 인상깊었습니다.

혼자 힘으로 프로젝트를 처음부터 끝까지 구상해보고 데이터를 설계해보고 함수를 설계해보는 경험이 많지 않았는데
어렵긴 했지만 그만큼 많은 것을 얻어갔습니다. 

개인적으로 이번 프로젝트에서 더 보기 편하고 효율적이고 깔끔한 구조를 만들려고 노력했습니다. 
그래서 리펙토링 하면서 코드가 깔끔해는걸 보면서 뿌듯함도 많이 느꼈습니다.

● 본인이 생각하는 본인 코드의 부족한 점




프로젝트 구조 구상에 더 욕심이 있습니다. 처음에는 사실 요리사도 함께 상호작용하는 프로젝트를 만들고 싶었는데 프로젝트 구조가 복잡해져서
기본적인 메뉴와 고객의 상호작용만 추가하였습니다.
나중에라도 요리사와 고객, 학생, 그리고 그걸 연결하는 시스템까지
유기적인 상호작용이 이루어져서 현실문제와 밀접하게 동작할 수 있는
프로그램으로 디벨롭 하고 싶습니다.


● 수업 방식에 대한 건의사항 (자유롭게 작성)

건의사항 없습니다. 수업 방식에 만족합니다.
